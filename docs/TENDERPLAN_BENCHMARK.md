# Benchmark: TenderPlan → Tender Intelligence Agent

Дата: 2026-09-11

TenderPlan взят как эталон продукта по UX и полноте тендерной аналитики. Цель — не копировать интерфейс или код, а перенести сильные продуктовые идеи в локальный агент с сохранением принципа **Ollama only / без OpenAI API**.

## Что у TenderPlan действительно сильнее

### 1. Поиск как сохранённый профиль, а не разовый запрос
- сохранённые «Ключи»;
- отдельные направления деятельности;
- исключения;
- поиск по названию, ОКПД2 и документации;
- регионы, заказчики, закон, цена, обеспечение, аванс;
- автоматическое появление новых подходящих закупок.

### 2. Поиск внутри документации
TenderPlan индексирует документацию и архивы, а не только карточку закупки. Это один из самых важных функциональных разрывов нашего агента.

**План для TIA:** отдельный слой `DocumentIndexer` → извлечение PDF/DOCX/XLSX/архивов → локальный полнотекстовый индекс → выдача совпавших фрагментов и ссылок на документ.

### 3. Аналитика рынка
TenderPlan показывает выборку по отрасли/ключу: объём рынка, динамику, сезонность, регионы, заказчиков и поставщиков.

**Уже добавлено в TIA:** `src/analytics/market.py` с агрегатами по площадке, региону, заказчику, закону, стоимости и AI-score.

### 4. Аналитика заказчика
Нужны:
- число закупок;
- средняя/медианная цена;
- регулярность закупок;
- средний срок оплаты;
- отмены/несостоявшиеся процедуры;
- жалобы и арбитраж;
- повторные закупки.

Часть этих данных нельзя честно получить из текущих live-карточек. Нужны исторические протоколы/контракты и внешние источники.

### 5. Аналитика конкурентов
Нужны участия, допуски, победы, среднее снижение и пересечение по заказчикам.

Это нельзя «сымитировать» AI. Сначала нужен исторический слой результатов торгов и участников.

### 6. Риск и вероятность победы
TenderPlan показывает риск участия и прогнозы нейросети.

**Для TIA:** AI-score уже есть. Следующий уровень — отдельные объяснимые компоненты:
- соответствие товару/услуге;
- цена;
- срок;
- обеспечение;
- аванс/оплата;
- сложность документации;
- историческая конкуренция;
- исторический заказчик.

Итоговый показатель должен быть не просто «балл AI», а `Fit / Risk / Competition / Win probability` с объяснением каждого компонента.

### 7. Рабочая CRM для тендеров
TenderPlan использует метки, ответственных, статусы и календарь.

**Для TIA:** следующий слой — статусы `Новый → Проверить → Участвуем → Документы → Подано → Ожидание → Победа/Проигрыш`, метки и дедлайны.

### 8. Уведомления
Сильная идея TenderPlan — не просто прислать тендер, а отслеживать изменения.

**Для TIA:** добавить события `новый`, `изменена цена`, `изменён дедлайн`, `изменена документация`, `отмена`, `повторная закупка`.

## Что НЕ надо копировать

- Облачную зависимость от чужой инфраструктуры.
- Закрытые AI/API-сервисы.
- Сложный интерфейс ради интерфейса.
- Платные данные, которые можно заменить локальной историей.

Наше конкурентное преимущество: **локальная база + локальный Ollama + прозрачные правила фильтрации + Telegram + Excel + возможность самостоятельно контролировать данные.**

## Приоритет внедрения

1. **P0:** исправить и довести до идеала Telegram UX: сохранённые ключи, группы фильтров, понятная сводка критериев, быстрые пресеты.
2. **P0:** документный поиск по вложениям.
3. **P0:** история изменений тендера и повторные уведомления.
4. **P1:** статусы/метки/календарь.
5. **P1:** аналитика выборки и заказчика.
6. **P1:** исторические результаты торгов и конкуренты.
7. **P2:** локальная модель вероятности победы на накопленной истории.

## Важное отличие

TenderPlan — зрелая коммерческая система с большой исторической базой. Поэтому функции вроде арбитража, реального рейтинга заказчика и статистики конкурентов нельзя получить только красивым Telegram-интерфейсом. Для них TIA должен сначала накопить или импортировать соответствующие данные. Это заложено в архитектурный план, а не заменяется выдуманными показателями.
