# Tender Intelligence Agent

Автоматический мониторинг коммерческих тендеров: **поиск → фильтрация → локальный ИИ-анализ → Telegram/Excel → SQLite**.

Проект рассчитан на Windows 10/11 и часовой пояс `Europe/Moscow`.

## Поддерживаемые площадки

- ЕИС (`eis`)
- B2B-Center (`b2b_center`)
- Фабрикант (`fabrikant`)
- RTS-Tender (`rts_tender`)
- ТМК (`tmk`)
- Росатом (`rosatom`)

**UniPro из проекта удалён. На его месте используется Фабрикант.**

## ИИ

ИИ работает **только локально через Ollama**:

- URL по умолчанию: `http://localhost:11434`
- модель: `qwen3:8b`
- endpoint: `/api/chat`
- OpenAI API в проекте не используется.

Если Ollama недоступен и `use_stub_when_no_key: false`, ошибка явно фиксируется в логе. Заглушка не должна незаметно выдавать результат за настоящий ИИ-анализ.

Перед первым запуском установите Ollama и модель:

```powershell
ollama pull qwen3:8b
```

Проверьте, что Ollama запущен:

```powershell
ollama list
```

## Установка на Windows

Откройте PowerShell в папке проекта:

```powershell
cd C:\Users\Ju4ara\Projects\tender-intelligence-agent
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Для площадок с браузерным JavaScript установите Chromium:

```powershell
python -m playwright install chromium
```

Создайте пользовательские настройки:

```powershell
copy config\config.example.yaml config\config.yaml
copy config\keywords.example.yaml config\keywords.yaml
copy .env.example .env
```

После этого отредактируйте `config\config.yaml` и `config\keywords.yaml`.

## Настройка ключевых слов

Файл `config\keywords.yaml`:

```yaml
include:
  - "подшипник"
  - "подшипники"
  - "полумуфта"

exclude:
  - "утилизация"
  - "вывоз мусора"

ai_context: "Коммерческие закупки промышленного оборудования и запчастей"
```

Фильтр учитывает словоформы, а затем система применяет дополнительные критерии тендера.

## Основные критерии

Через Telegram можно настраивать, в частности:

- минимальную и максимальную цену;
- необходимость аванса и минимальный процент аванса;
- максимальную отсрочку платежа;
- минимальный срок до окончания подачи заявок (по умолчанию 7 дней);
- обеспечение заявки — по умолчанию до 5%;
- обеспечение контракта;
- минимальный балл ИИ;
- список ключевых слов;
- включённые площадки.

Настройки Telegram хранятся отдельно для каждого пользователя.

## `.env`

Минимально для локального запуска ИИ достаточно настроек из YAML. Для Telegram:

```text
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
```

Дополнительно поддерживается email-уведомление через SMTP.

**Не помещайте токены, пароли и другие секреты в Git.**

## Локальная web-форма профиля поиска

Для настройки профилей в браузере доступна форма в стиле привычных систем управления тендерами. Она использует тот же \`SearchProfileStore\`, что и Telegram, поэтому критерии не расходятся между интерфейсами.

Запуск на Windows:

\`\`\`powershell
python -m src.main web
\`\`\`

После запуска откройте \`http://127.0.0.1:8080/\`. Форма поддерживает название ключа, ключевые/исключающие слова, регионы, площадки, диапазон начальной цены, аванс, постоплату, срок до подачи, обеспечение заявки/контракта и минимальный AI-балл. Web-интерфейс намеренно слушает только loopback и не публикует базу наружу.

## Telegram без токена

Если токен Telegram не задан и в конфигурации включён `dry_run_when_no_token`, уведомления не отправляются наружу, а фиксируются в логах. Это удобно для проверки пайплайна без реального Telegram.

## Что происходит за один цикл

1. Загружаются ключевые слова и настройки.
2. Сборщики получают тендеры с включённых площадок.
3. Ошибка одной площадки не должна останавливать остальные.
4. Выполняется нормализация данных.
5. Применяются ключевые слова и бизнес-фильтры.
6. Дубликаты отсеиваются через SQLite.
7. Подходящие тендеры анализируются локальным Ollama.
8. Результаты сохраняются в SQLite.
9. Подходящие тендеры отправляются в Telegram/email или попадают в экспорт.

## Excel и база

- SQLite: `data\tenders.db`
- Логи: `logs\agent.log`
- Excel и тестовые артефакты: `output\`

В Excel ссылки на тендеры должны быть кликабельными. Структура экспорта ориентирована на рабочий список закупок, без служебных полей вроде номера поиска и даты поиска.

## Логи

Лог пишется через ротацию (`RotatingFileHandler`), поэтому большой `agent.log` не должен бесконечно расти. Параметры:

```yaml
logging:
  file: "logs/agent.log"
  max_bytes: 5242880
  backup_count: 3
```

## GitHub Actions

В репозитории есть CI с `workflow_dispatch`. Он выполняет детерминированные тесты, регрессионные проверки B2B/фильтров и интеграционный тест Excel, после чего сохраняет Excel и SQLite как артефакты.

Есть отдельная диагностика браузерных площадок. Она сохраняет результат проверки в артефакт даже при сетевой недоступности конкретного портала. Поэтому сетевой сбой внешнего сайта не должен маскироваться под ошибку Python-кода.

## Проверка перед использованием

Локально рекомендуется выполнить:

```powershell
python -m compileall src
python -m unittest discover -s tests
python -m src.main status
python -m src.main once
```

Отдельно проверьте Ollama:

```powershell
ollama list
```

и наличие модели `qwen3:8b`.

## Важное ограничение live-проверок

GitHub Actions не имеет доступа к вашему локальному `localhost:11434`, поэтому наличие и работоспособность именно вашего Ollama проверяется только на вашей Windows-машине. Аналогично, доступность закрытых/ограниченных тендерных порталов может зависеть от сети, WAF, CAPTCHA и региона.
