## Название проекта

ТендерБот

## Сохранение состояния

Используются три основных файла:

PROJECT_STATE.md
PROJECT_LOG.md
PROJECT_DECISIONS.md

PROJECT_STATE.md:
Текущее состояние проекта.

PROJECT_LOG.md:
История работы.

PROJECT_DECISIONS.md:
Постоянные решения и договорённости.

---

## Правило продолжения работы

При переходе в новый чат проект не считать новым.

Нужно продолжать с последнего сохранённого состояния.

Важные изменения фиксировать в PROJECT_STATE.md и PROJECT_LOG.md.

Регистрация:
src/collectors/registry.py

## B2B-Center

Рабочий идентификатор площадки во всех слоях системы:

`b2b_center`

Не использовать варианты `b2b-center` и другие идентификаторы в config,
Telegram, registry или SQLite.

B2B-Center подключается через `BaseCollector` и `registry.py` наравне с ЕИС.
В Telegram пользователь может включать и выключать `b2b_center` через
`enabled_platforms`; фактический запуск также требует `enabled: true` в config.

Публичный поиск B2B-Center на 21.08.2026 возвращает один доступный набор
из 20 результатов; не эмулировать пагинацию параметром `page`, пока сайт
не начнёт возвращать отличающиеся страницы.

platform + external_id

## Telegram

Telegram используется для уведомления о релевантных тендерах.

Уведомление отправляется только после AI-анализа и проверки
min_relevance_score.

Текущий порог:
70

Не снижать порог только ради увеличения количества уведомлений.
Сначала оценивать качество AI.

---

## Правило изменения файлов

При необходимости заменить файл полностью:
выдавать полный актуальный текст файла.

Для автоматической замены использовать PowerShell.

Не предлагать пользователю вручную искать и менять отдельные фрагменты
в больших файлах, если файл можно заменить целиком.

---

## Правило диагностики

Перед изменением рабочего кода сначала посмотреть актуальный файл
и фактический результат выполнения.

Не менять несколько независимых компонентов одновременно без необходимости.
